The Windows side of the same story: Select-String and Invoke-RestMethod

PowerShell pipes objects, not text. For a code model that is a real advantage.

Why these two

Select-String (alias sls) is PowerShell's grep. Regex by default, recurses with -Recurse, inverts with -NotMatch. When an AI coding agent is working on a Windows box and needs to find every reference to a function, this is what it runs.

Invoke-RestMethod (alias irm) is PowerShell's curl — except it doesn't hand you a wall of JSON. It parses the response into a live object. irm $url then .items[0].id, and you're done. No jq required.

The twist: objects, not text

In Bash you pipe strings and parse columns with awk. In PowerShell you pipe [FileInfo] or [Process] objects and filter on properties: Where-Object Status -eq "Running". For a code model that is a real advantage — it reasons about fields by name instead of guessing which column holds what.

  • Discoverable. Get-Command *-Service* tells the agent what exists before it guesses.
  • Consistent. Every cmdlet is Verb-Noun. Learn one, predict the rest.
  • Composable. One pipeline, five tiny steps, no script file.
  • Honest about failure. Typed errors, not just "exit 1."

Different philosophy, same lesson: small tools with clear contracts are the interface language models were waiting for.
